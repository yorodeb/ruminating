# Logic League by HackForge

The *Logic League -- Ideathon* is an idea-generation and problem-solving event designed for Computer Science students.

The objective is to provide students with an environment where they can:

* Identify meaningful real-world problems.
* Explore problems through a Computer Science perspective.
* Develop innovative and technically feasible solutions.
* Practice problem decomposition and solution design.
* Collaborate with peers from different areas of interest.
* Present and defend their ideas clearly.

Rather than providing participants with completely open-ended problem
statements, the Ideathon will use a **structured framework** of broad Computer
Science domains and focused **insights**.

This structure provides enough guidance to help students get started while
still leaving substantial freedom for them to identify the problem and design
the solution themselves.

# Working Principle for Ideathon

The Ideathon will have five umbrella themes:

1. **AI/ML**
2. **Cybersecurity**
3. **Developer Tooling**
4. **Blockchain**
5. **Open Innovation**

The first four themes will contain a set of **insights**.

An insight is **not a predefined project or problem statement**. Instead, it
represents an area in which participants can investigate problems.
The **problem and solution are determined by the participants**.

# Evaluation Criteria

| Criteria                  | Description                                                         |
| ------------------------- | ------------------------------------------------------------------- |
| **Problem Understanding** | How clearly does the team understand the problem?                   |
| **Problem Relevance**     | Is the problem meaningful to the intended users?                    |
| **Innovation**            | Does the proposed approach offer a meaningful or novel perspective? |
| **Technical Approach**    | Is the proposed technology appropriate for the problem?             |
| **Feasibility**           | Can the proposed solution realistically be developed?               |
| **Impact**                | What potential value could the solution provide?                    |
| **Clarity**               | How clearly can the team communicate the problem and solution?      |

# Submission

Each participating team will submit their idea through a **GitHub repository**.
The repository may initially contain only the documentation and does not necessarily need to contain a fully implemented product. The primary purpose of the submission is to communicate the team's understanding of the problem and its proposed solution.

## Repository Requirements

Each team should create a **separate, empty GitHub repository** and use its `README.md` as the primary submission document.
The README should clearly explain the team's idea and should contain, at minimum, the following sections:

### 1. Problem Statement

- What is the problem?
- Who experiences it?
- Why is it a problem?
- What difficulties or inefficiencies does it create?

### 2. Existing Solutions
Teams should identify relevant existing solutions and explain their limitations or shortcomings.

### 3. Proposed Solution
Explain the team's proposed approach to solving the identified problem. The
explanation should focus on **what the solution does and how it addresses the
problem**, rather than simply listing technologies.

### 4. Key Features
List the major features or capabilities of the proposed solution.

For example:
- Feature A — brief explanation
- Feature B — brief explanation
Teams should prioritize the features that directly contribute to solving the identified problem.

### 5. Technical Approach
Explain how the proposed solution would work from a technical perspective.

- System architecture
- Major components
- Data flow
- Algorithms or methodologies
- APIs or external services
- Infrastructure requirements
- Security considerations

A diagram may be included where it helps communicate the architecture.

### 6. Technology Stack

List the technologies that the team intends to use.
For example:

```text
Frontend: React
Backend: Go
Database: PostgreSQL
ML: Python / PyTorch
Infrastructure: Docker
```

### 7. Expected Impact
Explain the potential value of the proposed solution.

- Who benefits from the solution?
- How does it improve the current situation?
- What could be achieved if the solution were successfully implemented?

### 8. Future Scope
Briefly describe how the project could be extended beyond the initial proposed solution.

- Additional features
- Larger-scale deployment
- Support for additional users or use cases
- Integration with other systems
- Future technical improvements
